# 05-模拟面试

> 模块文档 · 对应代码基线：master（Phase 6 已提交 d59a4fe）· 更新日期：2026-09-07

## 1. 功能概述
用户选简历（可空）+ 填 JD + 选方向（frontend/backend/test/algorithm/data/devops/fullstack）+ 题数（5/8/10/15）→ **AI 一次性生成全部题目**缓存 Redis → 聊天式逐题作答 → **边答边评**（每攒够 4 题异步评估一批）→ 答完自动提交评估 → **1 次 LLM 汇总** → 轮询展示报告（总分/逐题/优势/建议）。

## 3. 核心流程
```
【创建】POST /api/interviews/sessions {resumeId?, jdText, direction, questionCount}
  → 简历 parsed_text 加载（无简历 → 纯 JD 出题）
  → system：出题模板{方向/题数/简历} + JSON Schema + 防注入指令
  → user：{resumeText}/{jdText} 分别净化+动态分隔符包裹
  → LLM 返回 JSON 数组 → parseQuestionList（⚠️ 无围栏剥离）
  → 入库 status=IN_PROGRESS + questions_json → Redis SET interview:questions:{id} TTL 2h
  → 返回 {sessionId, direction, questionCount, firstQuestion}

【作答】POST /api/interviews/sessions/{id}/answers {questionNumber, answerText}
  → 校验：status=IN_PROGRESS、questionNumber == currentQuestion+1（按序作答）、未重复提交
  → 题目从 Redis 缓存读（miss 则 DB 回读并回写）
  → 入库 answer（含 question_text 冗余）→ currentQuestion 更新
  → 增量评估触发：currentQ % 4 == 0 或最后一题 → SETNX 批次锁 → XADD 增量批次消息
  → 未答完：返回 nextQuestion；答完：status=COMPLETED 返回 allDone

【增量批次评估】InterviewEvaluationConsumer（增量模式）
  → evaluateBatchRange：按题号范围查 answers → 单批 LLM 评估（≤4 题）
  → 结果存 Redis interview:batcheval:{sId}:{batch}（TTL 2h）+ SADD batches:done + 释放锁

【汇总】POST /api/interviews/sessions/{id}/evaluate（前端答完自动调）
  → 校验 status=COMPLETED → 置 EVALUATING
  → XADD type=summarize 消息（InterviewEvaluationProducer.sendSummarizeTask；T5 起替代原裸 new Thread）
  → 消费者 InterviewEvaluationServiceImpl.summarizeAndPersist：
      幂等（仅 EVALUATING 执行）→ 轮询 batches:done 最多 30s
      ├─ 批次齐 → 收集各批 JSON → 1 次 LLM summarizeBatches（perQuestion 从各批拼接）
      ├─ 汇总 LLM 失败 → degradeMerge 本地拼接取平均分
      └─ 批次不齐/为空 → 降级发全量评估消息（type 缺省=FULL：全量分批+汇总）
  → 入库 interview_evaluations → status=EVALUATED → 清理 Redis
  → 启动恢复：InterviewRecoveryRunner（ApplicationRunner）扫描 status=EVALUATING 会话补发 summarize

【消息类型】interview:evaluate:stream 消费三种消息（Consumer 按 body 字段区分）：
  - BATCH（含 batchNumber/qStart/qEnd）→ 增量批次评估，结果存 Redis
  - SUMMARIZE（type=summarize）→ 收集批次+1次汇总+入库（EVALUATING→EVALUATED）
  - FULL（无 batchNumber/type，兼容旧消息）→ 全量分批评估+汇总

【轮询】GET /api/interviews/sessions/{id}/evaluation
  → 返回 sessionStatus + （EVALUATED 时）报告字段；前端 3s 轮询
```

## 4. 实现细节
- **一次性出题的理由**：逐题生成每次答题等 5~10s 且无全局递进规划；一次性生成 + Redis 缓存，答题零延迟。
- **边答边评的理由**：答完后才评估要干等 15~30s；每 4 题异步评一批，提交时只剩 1 次汇总（3~5s）。
- **渐进式降级**：批次缺失 → 等 30s → 仍缺 → 全量评估兜底；汇总 LLM 失败 → 本地拼接平均分；任何路径都尽量产出报告。
- **批次防重**：Redis SETNX `:lock`（30s TTL）+ `batches:done` Set 双检。
- 出题/评估都走 BeanOutputConverter + guardOutput + ANTI_INJECTION_INSTRUCTION（与模块 02/03 一致）。
- 会话状态机：`CREATED(未用) → IN_PROGRESS → COMPLETED → EVALUATING → EVALUATED / FAILED`。
- 前端：localStorage 草稿 1.5s 防抖保存/提交后清除；allDone 后 1.5s 自动调 evaluate；3s 轮询至 EVALUATED/FAILED。

2. ~~消费组缺陷影响~~：✅ 已修（跨模块坑 #1 由 T3 修复：`ensureGroupExists` 幂等建组 + NOGROUP 自恢复，2026-09-07）。
3. ~~无 json 围栏剥离~~：✅ 已修（B1，2026-09-08）——`IPromptDefenseService.stripJsonFence` 剥离 ```json 围栏后解析，出题/评估/汇总/简历分析四调用点统一接入；PromptDefenseTest 增 6 用例（22 全绿）。
4. ~~数组索引假设~~：✅ 已修（B2，2026-09-08）——出题后 `renumberQuestions` 按数组顺序归一化题号 1..N（LLM 跳号/乱序自动修正，非连续时 log.info），`get(0)`/`>= size()`/`get(questionNumber)` 下标假设恒成立；历史会话数据本就连续无需迁移。
5. **⚠️ 批次锁竞态（会话级锁 key）**：`interview:batcheval:{sId}:lock` 不含批次号，若 30s TTL 内快速答完两批（如脚本/超快答题），后一批 SETNX 失败被跳过 → 该批永不增量评估，只能靠汇总 30s 等待后降级全量兜底（实测命中——B3 验证时 Q4→Q5 间隔 4s 再次命中 batch2 缺失；真人节奏不易触发，可接受，兜底链已验证）。后续若要修：锁 key 加批次号。
6. summarize/全量评估期间消费线程串行最长阻塞 30s（等批次）；批次消息先于汇总入队，正常情况无需等待。
7. ~~submitAnswer 无事务~~：✅ 已修（B3，2026-09-08）——`submitAnswer` 加 `@Transactional` 使 DB 多步原子（answer 入库/进度更新/置 COMPLETED 同事务）；**增量评估 XADD 移至事务提交后回调**（`TransactionSynchronization.afterCommit`，触发器改为提交后重读会话再判定），避免消费者读到未提交 answer 静默丢批次（跨模块坑 #8 同型）。
8. **前端 resetChat() 不清 pollTimer**：答题中"退出"后轮询仍跑（`getEvaluation(null)` 静默失败）；`resetAll()` 才清理。
9. **前端无法续答**：刷新/离开后进行中会话丢失；HistoryPage 无"继续面试"入口。
10. 面试问题缓存 2h TTL 过期后靠 DB questions_json 回读（设计正确，不是坑）。

# 01-数据模型

> 性质：参考文档 · 状态：基线 v1 · 更新日期：2026-09-22

## 1. 数据库表（PostgreSQL，库 ai_interview）

9 张业务表 + 1 张 Spring AI 自动建的 `vector_store`。全部 BIGSERIAL 主键、时间戳默认 NOW()。字段命名 snake_case，与实体驼峰自动映射（MyBatis-Plus 默认策略）。

| 表 | 用途 | 关键字段 | 关联 |
|---|---|---|---|
| `file_info` | 分片上传完成记录（秒传去重）。不变式：**有行 ⇔ 对应 OSS 对象存在**；删除所属知识库时同事务按 `storage_key` 清理（T25） | file_md5(唯一索引), storage_key, storage_url | — |
| `resumes` | 简历 | file_md5, parsed_text, analyze_status(PENDING/PROCESSING/COMPLETED/FAILED) | — |
| `resume_analyses` | 简历分析历史（一对多） | resume_id, overall_score, strengths_json, suggestions_json | → resumes.id |
| `knowledge_bases` | 知识库文档 | file_md5, kb_name, category, parsed_text, vector_status, chunk_count | — |
| `rag_chat_sessions` | RAG 会话 | session_title, kb_ids(JSON 字符串), is_pinned | — |
| `rag_chat_messages` | RAG 消息 | session_id, role(user/assistant), content, message_order, completed | → rag_chat_sessions.id |
| `interview_sessions` | 面试会话 | resume_id?, jd_text, direction, question_count, current_question, status(CREATED/IN_PROGRESS/COMPLETED/EVALUATING/EVALUATED/FAILED), questions_json | → resumes.id |
| `interview_answers` | 面试回答 | session_id, question_number(1-based), question_text(冗余), answer_text | → interview_sessions.id |
| `interview_evaluations` | 面试评估（一对多） | session_id, overall_score, per_question_json, strengths_json, improvements_json | → interview_sessions.id |
| `vector_store` | 向量（**Spring AI 自动建**，HNSW/COSINE/1024 维） | metadata 含 `kb_id`；删除用 JdbcTemplate：`DELETE FROM vector_store WHERE metadata->>'kb_id' = ?` | → knowledge_bases.id（软关联） |

### 状态机约定
- `resumes.analyze_status` / `knowledge_bases.vector_status`：PENDING → PROCESSING → COMPLETED / FAILED（Stream 消费者驱动）
- `interview_sessions.status`：IN_PROGRESS → COMPLETED → EVALUATING → EVALUATED / FAILED

### JSON 字段约定（存 TEXT，读取时 parse）
- `strengths_json` / `improvements_json` 类：字符串数组或对象数组（结构见各模块文档 §4）
- `questions_json`：`[{questionNumber, questionText, tags[]}]`
- `per_question_json`：`[{questionNumber, score, comment}]`
- `kb_ids`：`[1,2]` 数字数组 JSON 字符串

## 2. Redis Key 清单（db 1，统一 `common/RedisKeys.java` 管理）

| Key 模板 | 类型 | TTL | 用途 |
|---|---|---|---|
| `file:chunks:{md5}` | Set | 24h | 已上传分片序号 |
| `file:upload:{md5}` | Hash | 24h | 会话信息 {uploadId,totalChunks,fileName,fileSize,fileKey} |
| `file:etags:{md5}` | Hash | 24h | {partNumber → eTag} |
| `file:merge:{md5}` | String | Redisson 锁 | 合并互斥 |
| `interview:questions:{sessionId}` | String(JSON) | 2h | 题目缓存（miss 从 DB questions_json 回读） |
| `interview:batcheval:{sessionId}:{batch}` | String(JSON) | 2h | 增量评估批次结果 |
| `interview:batcheval:{sessionId}:batches:done` | Set | 2h | 已完成批次号 |
| `interview:batcheval:{sessionId}:lock:{batch}` | String | 30s | 批次并发锁（SETNX，key 含批次号——T15 修复后批次间不互斥） |

✅ 面试相关 key 已统一到 `RedisKeys` 常量与格式化方法（T6 已修，2026-09-07），实现类无字面量。

## 3. Redis Stream 清单（统一 `common/StreamKeys.java` 管理）

| Stream | Group | Consumer 前缀 | 消息体 | 消费逻辑 |
|---|---|---|---|---|
| `resume:analyze:stream` | `analyze-group` | `analyze-consumer-` | {resumeId, content, retryCount} | ResumeAnalysisConsumer → LLM 分析 → resume_analyses |
| `knowledgebase:vectorize:stream` | `vectorize-group` | `vectorize-consumer-` | {kbId, content, retryCount} | VectorizeConsumer → 切分+embedding → vector_store |
| `interview:evaluate:stream` | `evaluate-group` | `evaluate-consumer-` | {sessionId, retryCount} 或 +{batchNumber,qStart,qEnd} | InterviewEvaluationConsumer → 全量评估 或 增量批次评估 |

公共参数：BATCH_SIZE=10 条/次、POLL_INTERVAL_MS=1000ms、MAX_RETRY_COUNT=3（应用层）、STREAM_MAX_LEN=1000。
重试机制：失败重 XADD（retryCount+1），≥3 次 markFailed，**都 ACK 原消息**。

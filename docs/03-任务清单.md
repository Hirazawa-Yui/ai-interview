```powershell
# pwsh：在 backend/ 下执行——注入 .env 到当前会话后启动
cd backend
Get-Content .env | ForEach-Object { if ($_ -match '^\s*([A-Z_]+)=(.*)$') { Set-Item "Env:$($matches[1])" $matches[2] } }
mvn spring-boot:run
```

### T20 修复 RAG 流式渲染（SSE 丢换行 + 响应式丢失）

- 状态：🔧 代码 + 自动验收完成（2026-09-22），**待用户浏览器复核**后提交

- 根因（规划阶段实测定位，两个独立 bug）：
  1. **SSE 逐行解析丢换行**：Spring 的 SSE 编码器会把一个分片内部的换行拆成**同一事件里的多个 `data:` 行**（分片 `"标题\n"` → 线上 `data:标题\ndata:\n\n`），而旧实现 `line.trim()` 后对每个 `data:` 行独立派发 → 换行符丢失 → `marked` 只能渲染成一个扁平段落。刷新后内容从数据库读回（换行完好）→ 正常，这正是"刷新才对"的原因
  2. **Vue 响应式丢失**：`doChat` 把**裸对象** push 进 `chatMessages`，之后 `aiMsg.content += chunk` 改的是裸对象，绕过 reactive 代理的 set 陷阱 → 流式期间不重渲染，直到 `finally` 里 `chatLoading.value = false` 才整体刷一次 → "一整坨"
- 改动（3 文件，纯前端）：
  - 新增 `frontend/src/utils/sse.js`：零依赖规范 SSE 解析器（同事件多行 `data:` 用 `\n` 拼接、遇空行派发一次、兼容 `\r\n`、只剥一个前导空格、支持半行跨块）
  - `frontend/src/api/rag-chat.js`：`streamChat` 读循环改用该解析器

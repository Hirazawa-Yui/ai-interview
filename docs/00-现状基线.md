## 4. 横切机制（改代码前必读）

### 4.1 统一响应 Result<T>
- 所有接口返回 `{code, message, data}`，**HTTP 状态码恒为 200**（`WebExceptionHandler` 用 `@ResponseStatus(HttpStatus.OK)` 统一处理）。
- `Result.ok(data)` / `Result.fail(ErrorCode, msg)`；前端 axios 拦截器按 `code===200` 解包。
- `ErrorCode` 按模块分号段：1xxx 通用、2xxx 简历、3xxx 面试、4xxx 文件、6xxx 知识库、7xxx AI 服务、8xxx 限流（预留）、9xxx 日程（预留）。
- 异常体系：`BusinessException`（业务可预期）→ WebExceptionHandler 分门别类处理（参数校验/AI 网络异常/404/兜底）。

### 4.2 Redis Stream 异步模板（AbstractStreamProducer/Consumer）
- 生产者：`sendTask(payload)` → XADD + MAXLEN 裁剪（`STREAM_MAX_LEN=1000`），失败回调 `onSendFailed`（子类更新状态 FAILED）。
- 消费者：`@PostConstruct` 启动单线程守护循环，XREADGROUP（`BATCH_SIZE=10`、`POLL_INTERVAL_MS=1000ms`、只读新消息 `>`）。
- 应用层重试：失败重 XADD（retryCount 字段，最多 `MAX_RETRY_COUNT=3`），最终失败 `markFailed`；**无论成败都 ACK 原消息**。
- 三对实例（见 docs/01-数据模型.md Stream key 清单）：简历分析、知识库向量化、面试评估。
- **⚠️ 已知缺陷**：`createGroup()` 失败被统一吞掉（假设 BUSYGROUP）。Stream key 不存在时（首条消息 XADD 前）建组失败也被吞，消费者将永远 NOGROUP 空转。详见坑位 §5。

### 4.3 Boot 4 手动配置类（新增依赖前必须验证自动配置兼容性）
| 类 | 原因 |
|---|---|
| `MybatisPlusConfig` | MP 3.5.9 自动配置在 Boot 4 下失效 → 手动 `MybatisSqlSessionFactoryBean` + SqlSessionTemplate + 空 `MybatisPlusInterceptor` |
| `RedissonConfig` | redisson starter 不兼容 Boot 4 → 手动单机 Config（yml 的 spring.data.redis 值） |
| `LlmConfig` | Chat/Embedding 自动配置被 Application 排除 → 手动 OpenAiApi（10s 连接/60s 读超时）+ ChatModel（temperature 0.2）+ ChatClient + EmbeddingModel（1024 维） |
| `RedisConfig` | `RedisSerializer.json()`（Jackson2JsonRedisSerializer 已废弃）；StringRedisTemplate 用于 Stream/Lua |
| `JacksonConfig` | NON_NULL、忽略未知属性、JavaTimeModule |

`Application.java` 还排除了 Spring AI 音频/图片/审核自动配置（不做语音面试）。虚拟线程已启用（Java 21）。

### 4.4 Prompt 防护编排（所有 LLM 调用必须走）
`IPromptDefenseService`：调用前 `sanitizeAndWrap(label, text)`（正则净化 + 动态分隔符包裹），调用后 `guardOutput(llmResponse)`（投降语检测）。System prompt 末尾追加 `PromptSecurityConstants.ANTI_INJECTION_INSTRUCTION`。详见 `docs/modules/02-Prompt注入防护.md`。

### 4.5 无登录体系
全平台无用户概念、无 token、无鉴权过滤层。数据全局共享（单机自用工具形态）。新增功能沿用此形态，除非用户明确要求加登录。
